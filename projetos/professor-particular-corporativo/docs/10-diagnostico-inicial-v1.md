# 10 — Diagnóstico Inicial v1

**Projeto:** Professor Particular Corporativo de Competências Digitais  
**Domínio-piloto:** Microsoft Excel / Office  
**Públicos:** profissional corporativo e educando do PMT  
**Versão:** 1.0  
**Status:** especificação operacional inicial

## 1. Objetivo

Definir a primeira experiência prática do usuário com o agente, desde a coleta de contexto até a geração do primeiro mapa de competências e plano individual.

O diagnóstico deve ser suficientemente curto para manter o engajamento, mas suficientemente amplo para evitar uma classificação baseada em uma única habilidade.

## 2. Estrutura

1. Perfil e contexto;
2. Autopercepção;
3. Experiência e uso das ferramentas;
4. Tarefas diagnósticas;
5. Síntese e plano inicial.

## 3. Perfil e contexto

Coletar, conforme finalidade: grau de instrução, formação, cargo/função ou situação educacional, área, experiência profissional, principais responsabilidades, objetivo, ferramentas utilizadas, frequência de uso, sistema operacional, versão do Office/Microsoft 365, sistemas de trabalho e outros conhecimentos técnicos relevantes.

Também perguntar quais tarefas digitais mais consomem tempo, geram erros ou causam insegurança.

## 4. Autopercepção

Solicitar avaliação de 1 a 5 para Word, Excel, PowerPoint, e-mail/Outlook, organização de arquivos, internet/pesquisa, colaboração e IA quando pertinente. Para o domínio prioritário, aprofundar por grupos de competência.

A autopercepção é hipótese, não resultado final.

## 5. Experiência declarada

Perguntar sobre situações reais, evitando depender somente de termos técnicos. Para Excel, investigar criação de planilhas, fórmulas, buscas em outras tabelas, gráficos, tabelas dinâmicas, organização de bases e preparação de relatórios.

## 6. Tarefas diagnósticas

Começar com poucas tarefas contextualizadas e progressivas, em vez de aplicar uma prova de 20 competências.

### Tarefa A — Operação básica

Manipular e organizar uma pequena tabela. Amostra EX01–EX04.

### Tarefa B — Cálculo

Construir fórmulas e indicadores simples. Amostra EX05–EX07.

### Tarefa C — Lógica/referência

Aplicar condição ou referência adequada. Amostra EX06–EX09.

### Tarefa D — Análise

Filtrar, organizar ou resumir dados. Amostra EX10–EX12 e, quando pertinente, EX17.

### Tarefa E — Integração

Resolver pequena demanda profissional escolhendo os recursos adequados. Pode amostrar EX13–EX20.

## 7. Formato da tarefa

Cada tarefa deverá conter contexto, objetivo, dados necessários, instrução inicial, espaço para execução e critério de conclusão.

Quando a finalidade for avaliar tomada de decisão, não informar previamente qual recurso do Excel deve ser utilizado.

## 8. Avaliação da execução

Registrar, quando possível:

- correto/incorreto;
- autonomia;
- tipo de erro;
- ajuda necessária;
- capacidade de corrigir;
- capacidade de explicar;
- transferência para uma variação.

### Autonomia

- não realizou;
- realizou com orientação intensa;
- realizou com orientação pontual;
- realizou sozinho;
- realizou sozinho e explicou/otimizou.

## 9. Ramificação adaptativa

### Desempenho baixo

Reduzir dificuldade e verificar pré-requisitos.

Exemplo: falha em EX05 → verificar operações básicas → verificar referência de célula → novo exercício.

### Desempenho adequado

Avançar para maior complexidade.

### Desempenho alto

Pular tarefas básicas e testar aplicação/transferência.

### Contradição

Se autopercepção e execução forem muito diferentes, realizar pelo menos uma tarefa adicional antes da conclusão.

### Incerteza

Se a evidência não for suficiente, classificar como **não avaliada/incerta**, não inventar um nível.

## 10. Diagnóstico por amostragem

O diagnóstico não precisa cobrir as 20 competências com profundidade. O objetivo é obter evidências suficientes para uma decisão pedagógica.

Competências não testadas permanecem como **não avaliadas**.

## 11. Tempo e carga

Hipótese inicial para validação:

- perfil: 5–10 min;
- autopercepção/experiência: 5–10 min;
- tarefas: 15–30 min;
- síntese: poucos minutos.

Os tempos deverão ser validados nas primeiras aplicações.

## 12. Síntese apresentada ao usuário

**Seu perfil** — contexto resumido.

**Seu nível atual** — estimativa por domínio.

**Você já consegue** — pontos fortes.

**Vale desenvolver** — principais lacunas.

**Por onde começar** — prioridades justificadas.

**Seu próximo passo** — primeira atividade.

## 13. Mapa técnico interno

| Campo | Exemplo |
|---|---|
| Domínio | Excel |
| Competência | EX13 |
| Nível | 2 |
| Confiança | Alta |
| Autopercepção | 4 |

| Importância | Alta |
| Frequência | Diária |
| Prioridade | Muito alta |
| Status | Lacuna |
| Última avaliação | data |

## 14. Status das competências

- **Consolidada** — suficiente para o objetivo atual;
- **Em desenvolvimento** — requer prática;
- **Prioritária** — lacuna relevante;
- **Pré-requisito** — necessária para outra competência;
- **Não avaliada** — evidência insuficiente.

## 15. Plano individual

No MVP, gerar apenas 3–5 prioridades. Para cada uma: motivo da seleção, objetivo, atividade, exercício, desafio, teste e critério de avanço.

## 16. Exemplo

```text
OBJETIVO
Ganhar autonomia em Excel para tarefas administrativas.

DIAGNÓSTICO
Nível intermediário inicial.

PONTOS FORTES
- organização de tabelas;
- fórmulas básicas;
- filtros.

PRIORIDADES
1. Referências — pré-requisito para buscas.
2. PROCX — necessidade frequente no trabalho.
3. Tabela dinâmica — necessária para relatórios.
4. Interpretação — melhorar comunicação dos resultados.

SEQUÊNCIA
M1 — Referências
M2 — Buscas
M3 — Tabela dinâmica
M4 — Projeto aplicado
```

## 17. Feedback

O feedback deve ser específico, respeitoso, baseado em evidências, orientado à ação e sem rótulos pessoais.

Evitar: "Você é ruim em Excel."

Preferir: "Você demonstrou segurança em cálculos básicos, mas precisou de orientação para manter uma referência fixa. Vamos trabalhar essa habilidade antes de avançar para buscas."

## 18. Reteste

Avaliar a mesma competência com tarefa equivalente ou variação. O objetivo é medir transferência, não apenas repetição.

## 19. Experiência do usuário

O agente deve funcionar como professor particular, não como formulário burocrático. Deve dar instruções claras, permitir tentativa, não revelar respostas durante a avaliação, registrar erros sem constrangimento, fornecer feedback e adaptar a linguagem ao público.

## 20. Adaptação por público

### Corporativo

Priorizar produtividade, redução de erros, autonomia, tarefas do cargo e situações reais.

### PMT

Priorizar autonomia digital, preparação para o mundo do trabalho, situações profissionais simuladas, aprendizagem consciente e capacidade de continuar aprendendo.

## 21. Banco inicial de tarefas

Começar com poucas tarefas de alta qualidade. A expansão deve considerar quais tarefas diferenciam bem os níveis, geram ambiguidades, são longas demais, deixam competências subavaliadas ou revelam dificuldades recorrentes.

## 22. Melhoria contínua

```text
Aplicação → Resultado → Análise dos erros → Revisão da tarefa → Nova versão
```

Alterações importantes devem ser versionadas.

## 23. Critério de sucesso do MVP

O diagnóstico será considerado funcional quando conseguir, com carga razoável:

1. identificar o contexto;
2. estimar nível com confiança adequada;
3. detectar lacunas relevantes;
4. evitar classificações sem evidência;
5. selecionar prioridades coerentes;
6. gerar trilha individual;
7. permitir teste e reteste.

## 24. Próxima etapa

Construir o **Banco de Tarefas Diagnósticas v1**, começando por Excel e definindo para cada tarefa: código, competências, pré-requisitos, enunciado, base necessária, resposta esperada, critérios de correção, erros típicos, níveis 1–5, pistas permitidas e variações para reteste.
